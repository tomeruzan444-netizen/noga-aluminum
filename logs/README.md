## איך זה עובד

- **קובץ ליום:** לכל יום עבודה יש קובץ בשם `YYYY-MM-DD.md` (למשל `2026-08-27.md`).
- **מתי מתעדכן:** קלוד מעדכן את קובץ היום השוטף לאורך העבודה (אחרי כל משימה שמסתיימת), וסוגר אותו בסוף היום.
- **מה נכתב בכל פעולה:**
  - **מה ביקשת** - הבקשה שלך במילים שלך (בקצרה).
  - **מה בוצע** - הפעולות שקלוד עשה.
  - **מה שונה** - קבצים / עמודים / הגדרות שהשתנו.
  - **בדיקות שהורצו** - אימותים (build, בדיקת חי, ספירת מופעים וכו').
  - **סטטוס** - פורסם / הושלם / ממתין.
- **מועמדים לאוטומציה:** בכל יום סעיף שמסמן פעולות חוזרות ששווה לייעל, ולמטה כאן רשימה מצטברת.

## מועמדים לאוטומציה (רשימה מצטברת)

מעודכן לפי מה שחוזר על עצמו בפועל. מדורג לפי כדאיות:

1. **סקריפט יצירת עמוד עירוני (הכי משתלם)** - כל עמוד חדש עובר אותו תהליך: בדיקת כפילות, כתיבת JSON לפי טמפלייט, הוספה ל-CITIES, לינקים ב-mainNav ובפוטר, pages-index, lastmod, build, publish, אימות. סקריפט מחולל (`scaffold-city-page.mjs`) שמקבל: שם עיר, סוג שירות (חלונות/מעקות/גדר), זווית ייחודית ותמונה - יחסוך את רוב העבודה הידנית.
2. **חוסן FTP מובנה ב-publish.mjs** - ההעלאה נכשלת שוב ושוב (ETIMEDOUT / ECONNRESET / 421 / קובץ זמני `.in.*` תקוע). כדאי לבנות לתוך הסקריפט: ניסיונות חוזרים אוטומטיים + ניקוי קבצים זמניים תקועים לפני העלאה. זה חוזר כמעט כל פרסום.
3. **סקריפט רישום עמוד אחד (`register-page.mjs`)** - מרכז את 4-5 עדכוני הרישום (pages-index, lastmod, CITIES, mainNav, footer) לפקודה אחת.
4. **סקריפט שילוב ביטויים** - התהליך (קריאת עמוד, מציאת עוגן ייחודי, הוספה עם ספירת אימות, עדכון lastmod) חוזר בכל בקשת "שלב ביטויים". חלק הניתן לאוטומציה: האימות והרישום; המיקום הטבעי עדיין דורש שיקול דעת.
5. **היגיינת שמות קבצי תמונה** - כל תמונה שמתווספת עם רווחים בשם משונה ידנית למקפים. אפשר סקריפט שמנרמל אוטומטית כל webp חדש בתיקיית התמונות.
6. **סקריפט אימות חי (`verify-live.mjs`)** - בדיקת HTTP 200 + נוכחות מחרוזת מפתח, שחוזרת אחרי כל פרסום.
